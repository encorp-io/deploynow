        01
        
Make your repo DeployNow-enabled

        
Paste this into your AI coding agent. It adds a production Dockerfile, a GitHub Actions workflow that builds your image, a compose file, .env.example and a health check.

        

          

            prompt
            
          


Make this repository DeployNow-ready, following https://deploynow.encorp.ai/downloads/deploynow-ready.md. Add:
- a multi-stage production Dockerfile (non-root, listens on 0.0.0.0:$PORT, HEALTHCHECK) and a .dockerignore
- .github/workflows/docker-publish.yml that builds linux/amd64 and linux/arm64 images on every push to main and on v* tags, and pushes them to ghcr.io/<owner>/<repo>
- a docker-compose.yml for DeployNow: uses that image, expose instead of ports, env_file: .env, named volumes for data, healthchecks, and any database or cache the app needs
- a .env.example with every variable the app reads (placeholders only; secret names contain PASSWORD, SECRET, TOKEN or KEY)
- a GET /health endpoint if there is none, and a short DEPLOY.md
Never commit real secrets. Keep local development working.

Security and access

    
Root on every machine
deserves serious locks.

    

      
Passkeys and 2FA
TOTP and WebAuthn passkeys for every account, and one switch to require them for admins.

      
Single sign-on
Google, Microsoft or any OpenID Connect provider.

      
Fine-grained roles
Viewer, operator, admin and owner, granted per machine and per project.

      
AI access with limits
OAuth 2.1 for MCP apps, capped at the level you approve and revocable in one click.

      
Full audit log
Who did what, where and when, for every change, including every AI tool call.

      
mTLS agents
Agents dial out over mutual TLS. Nothing listens on the remote machine.

FAQ

      
Questions,
answered.

      
Something missing? Ask on GitHub.

    

    

      

        What is DeployNow?
        
DeployNow is an open-source, self-hosted deploy platform for Docker machines, built AI-first. It deploys and runs your apps, domains, secrets, monitoring and backups on servers you own, and lets AI agents such as Claude, ChatGPT and Cursor deploy and operate them over MCP. It replaces Portainer and Dokploy.

      

      

        Is it free and open source?
        
Yes. DeployNow is free and open source under the MIT license. You host it yourself; there is no paid tier and no account with us. It is provided as is, so read the terms.

      

      

        How do I install it?
        
Run curl -fsSL https://raw.githubusercontent.com/encorp-io/deploynow/main/setup.sh | sudo bash on a Linux server or a Mac. On Windows with Docker Desktop, run irm https://raw.githubusercontent.com/encorp-io/deploynow/main/setup.ps1 | iex in PowerShell. It installs Docker if needed, asks for a domain, port, admin email and password, and starts DeployNow.

      

      

        Can my AI agent deploy my app?
        
Yes. DeployNow has a built-in MCP server at /mcp with OAuth. Add it as a custom connector in Claude, ChatGPT, Cursor or Claude Code, pick Read only, Operate or Admin, and the agent can list apps, deploy, read logs, roll back and run backups. It can never delete anything or read secret values, and every call is in the audit log.

      

      

        How do I make my repository DeployNow-ready?
        
Paste the prompt above into your AI coding agent, or install the free deploynow-ready skill. It adds a production Dockerfile, a GitHub Actions workflow that builds and pushes a multi-arch image to GHCR, a docker-compose.yml, a .env.example, a health endpoint and a DEPLOY.md.

      

      

        How is it different from Portainer and Dokploy?
        
DeployNow does container management like Portainer and app deploys like Dokploy in one app, and adds encrypted backups with restore drills, machines behind NAT through an mTLS agent, uptime checks, Prometheus metrics, self-update with rollback and an MCP server for AI agents.

      

      

        Does it work with servers behind NAT?
        
Yes. A small agent on the remote machine dials out to DeployNow over mutual TLS, so the machine needs no open ports. DeployNow also manages machines over SSH, Docker TLS and the local Docker socket.

      

      

        What do I need to run it?
        
A Linux machine (amd64 or arm64) with at least 1 GB of RAM. DeployNow runs as a single container with an embedded SQLite database, and the installer sets up Docker for you.
